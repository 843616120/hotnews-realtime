# 07 版本源码与代码审计

## 版本与阅读路径

根 [`pom.xml`](../../pom.xml)把 Java 目标设为 8、Flink 1.17.0、Scala 2.12；[`flink-rolesachieve/pom.xml`](../../flink-job/flink-rolesachieve/pom.xml)为 MySQL Connector/J 8.0.28、Jedis 3.3.0 和可选 `day4-rocksdb` Profile。Compose Flink 镜像为 `flink:1.17.0-scala_2.12-java11`；Java 8 编译目标与 Java 11 运行环境不同，升级时要重新核对连接器、打包类加载、状态序列化和 Savepoint 兼容。父 POM 的某些依赖管理条目不是“实际作业使用了该连接器”的证据；以每个模块依赖及最终 shaded JAR 为准。

沿消息的真实路径读源码：`generator/generate_data.py` -> `common/FlinkSourceUtil` -> `flink-join/ArticleJoinBehavior` (ETL、Watermark、Join、旁路) -> `RoleStreamUtil` (防重) -> A/B/C (窗口、定时器、输出) -> `Day5SinkJob` (分流) -> `Day5MySqlSink` / `Day5RedisRankSink` -> SQL/独立基准/现场 JSON。每一步先追踪业务 Key、`event_time`、状态创建/清理、异常路由，再检查能否在故障重放下重现业务键。不把注释当作已验证功能，也不推断一段代码是否由 AI 生成；以下是**针对提交代码的人工审计风险**。

## 至少三项可定位的风险

| 风险与源码 | 影响、证据和处理方向 |
| --- | --- |
| [`Achieve_roleC`](../../flink-job/flink-rolesachieve/src/main/java/Achieve_roleC.java) 每次点击回看并重算同 IP 明细；主告警无 `article_ids[]` | 热 IP 的单 Key CPU/状态可能膨胀，且 PDF 规定的输出字段缺失。Day 4 `IpWindowStateJob` 有该字段但使用不重叠窗口，不能直接替换。需保持 C 的逐点击回看语义，补字段及高热点压测/正例测试。 |
| [`Day5MySqlSink`](../../flink-job/flink-rolesachieve/src/main/java/Day5MySqlSink.java) 的 C UPSERT 无修订号 | 从更旧快照反向回放可能用旧活跃告警覆盖新撤销；A/B 的单调保护不自动覆盖 C。应增加告警 revision/事件时间比较，并做有活跃 C 的重放试验。 |
| [`Day5RedisRankSink`](../../flink-job/flink-rolesachieve/src/main/java/Day5RedisRankSink.java) 的最新 Key 仅保留 2h | Key 过期后旧窗口/旧修订号失去比较基准，同窗口重放还可能续期。需持久化高水位或给出超过 TTL 的回放策略。 |
| [`ArticleJoinBehavior`](../../flink-job/flink-join/src/main/java/ArticleJoinBehavior.java) 的维度状态 2h TTL、行为乱序等待 65m/有界 2h | 状态过期、文章缺失或空闲时，业务行为可能进入待回放且末端窗口推迟。监控 `REPLAY_REQUIRED` 和状态量，保证 Topic 保留期，空闲分区/先到行为做固定回放。 |
| [`Day6BackpressureJob` 的隔离作业](../../flink-job/flink-rolesachieve/src/main/java/Day6BackpressureJob.java)只使用延迟 Sink | `--target=mysql|redis` 命名不等于真实网络/数据库写入；不得把吞吐、Lag、最后一条延迟当主链路 p95。需配合真实 Sink 指标再给容量结论。 |

另有已发生的兼容故障：Savepoint 恢复首轮 `No suitable driver found`，在 JDBC Sink 初始化显式加载驱动并重新打包后再恢复；见 [Day 5 现场证据](../06-Day5-Checkpoint与Savepoint记录.md)。这说明依赖在 JAR 中也不能跳过 Flink 类加载器下的运行验证。规则 B 当前是 PDF 所要求的 **10 分钟滚动窗口**，旧 Word 中称“PDF 要求 10 分钟滑动”的判断已过时，不应沿用。`HotNewsKafkaSourceJob` 仍是原始文本接入演示，不是业务作业。

## 回归与结论

[`RoleRulesTest`](../../flink-job/flink-rolesachieve/src/test/java/RoleRulesTest.java)覆盖 A 的 999/1000/1001、B 分类排序/修订、C 49/50/51 与阅读 1999/2000 ms、去重 TTL、先到/晚到关联等边界；[`Day5SinkContractTest`](../../flink-job/flink-rolesachieve/src/test/java/Day5SinkContractTest.java)核对绑定参数与唯一键 UPSERT；独立 SQL 按窗口比较日志。现有证据见 [测试矩阵](08-测试报告与验收矩阵.md)，但测试通过不代表旧 Checkpoint 对 C、Redis TTL 过期的外部幂等已通过。

**结论：**提交前需要复核并行作业的状态/连接器兼容、主链路资源与输出字段。审计的目标是指出可复现的逻辑、性能、可靠性风险，不是凭空声称修复或编造源码阅读结果。
